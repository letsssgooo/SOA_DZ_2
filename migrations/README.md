# Миграции PostgreSQL

Каталог подключается к `/flyway/sql` контейнера Flyway только для чтения.
SQL выполняется командой `make migrate`, применение и историю ведёт Flyway
в таблице `flyway_schema_history`.

Версионные миграции:

1. `V1__create_products.sql` — таблица товаров и ограничения полей.
2. `V2__add_products_status_index.sql` — индекс по статусу.
3. `V3__add_products_updated_at_trigger.sql` — функция и триггер обновления даты.
4. `V4__allow_products_created_at_updates.sql` — снятие защиты `created_at` от прямых SQL-обновлений.

`id`, `created_at` и `updated_at` заполняются БД при вставке. При обновлении
триггер задаёт только `updated_at` через
`clock_timestamp()`, включая обновление статуса на `ARCHIVED`.
В отличие от времени начала транзакции, это значение отражает время выполнения
обновления и может меняться при нескольких обновлениях внутри одной транзакции.
`created_at` остаётся прежним, если поле не указано в `UPDATE`, но его можно
изменить прямым SQL-запросом. HTTP API не принимает это поле в запросах.

Пустые SQL-заглушки не создавать: после применения Flyway сохраняет
контрольную сумму файла. Применённые миграции не редактировать; дальнейшие
изменения оформлять следующими версиями. Исходные три миграции сохранены
с контрольными суммами применённой истории; изменение функции выполняет `V4`.

Миграции не дублировать в `/docker-entrypoint-initdb.d` PostgreSQL.
